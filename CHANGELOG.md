# HackProof Changelog

All notable changes to HackProof are documented here.

## [Unreleased]

### Fixed (2026-10-21 sweep #3 — app-v1.0.5)
- **The exam page now honors the privacy promise for license storage.** PRIVACY.md has always said the license key is kept only in the browser's memory unless the student explicitly checks "Remember on this device" — and the course page always worked that way — but the exam page stored the key (and the student's name) in localStorage unconditionally when the student began the exam. The exam gate now carries the course page's own opt-in: the same "Remember on this device" checkbox with the same semantics (checked = stored in this browser only; unchecked = session-only, and any previously stored copy is removed). The verified key is held in the page's memory for the session, so certificate delivery and the copy-my-key button work exactly as before for students who never opt in. The gate's saved-value reads are also storage-failure-proof now, like every other storage access on the page: a browser that refuses localStorage gets a working session-only exam instead of a blank page. A behavioral test (the page's real code under a stub DOM) pins all of it, including that the app's bundled exam copy inherits the fix. This is the one website change in this release; it is confined to the exam page's storage logic.
- **The emailed certificate wears the academy palette.** The payments service's finished certificate (`payments/hackproof_pay/certgen.py`) was the one certificate left on the website's house-green tokens when the app certificate got its contrast-proven academy palette in app-v1.0.4. It now uses the same tones the app certificate proved: deep academy emerald for accents (8.44:1 on the cream stock), the derived small-print tone (12.81:1), and certificate gold only as emphasis on the near-black page ground (8.31:1) — gold never carries text on the cream stock, where it measures 2.34:1. Every text/background pairing in the emailed certificate measures at least 4.5:1 (worst case 7.63:1 against the stock's darker stop), recomputed from the shipped values and pinned by a new payments-suite test. Payments-side only: the app and website certificate files are byte-identical to before. The payments service is still not deployed; this is code correctness, not a go-live.
- **Certificate delivery answers tell the truth.** The certificate service's response reported `delivered: false` for a certificate it had just emailed (the response was built from the pre-send record), and on the resubmission path it marked a certificate delivered even when the send had failed. Both paths now report and record the delivery state as it actually stands, pinned by a new test.
- **A non-object JSON body gets a 400, not a 500.** Every POST route of the payments service takes a JSON object; a JSON list or string body used to crash the admin review-resolve route into a bare 500. It is refused up front with the same "JSON object body required" answer the order route already gave.
- **My Premium no longer claims an email that never went out.** When an order's delivery record says the license email did not go out (`claim_only` / `failed` — SMTP off or the send failed), the paid panel said "your license key has been emailed to you" anyway. It now says the email didn't go out and presents the key in-app — the claim path working as designed — and the long-standing test for the genuinely-emailed case is unchanged.
- **The Windows version resource tells one story.** The spec's numeric `filevers`/`prodvers` tuples had lagged at 1.0.3.0 through two bumps that updated the version strings; all version fields now agree at 1.0.5.

### Changed (2026-10-20 namesake palette — app-v1.0.4)
- **The app wears the academy's own colors.** HackProof is Sentinel's academy, and the Windows app now carries its own palette instead of the house Sentinel green: ink-black surfaces, a deep **academy emerald** (`#1da463` — deliberately not the fleet `#2ee06f`) as the primary, and **certificate gold** (`#c9a227`) as the accent, the color of the seal on the certificate the course exists to earn. Colors only — no behavior, layout, wording, or flow changed anywhere. The palette lives in one place (`app/hackproof_app/gui/theme.py`): the locked constants plus tones derived from them by documented mixes, all pinned by tests, every rendered text/background pair at WCAG AA or better (weakest pair 5.17:1). The bundled course pages carry the same palette via the bundler's `BRAND_MAP` (which now also retints the website's house-green tokens in the bundled copies only), the app's own HTML assets and the payment amount readout follow the theme, and the icon was regenerated in the academy colors from the same drawing code. The website keeps the house design untouched, the emailed certificate is unchanged, and the app's functional danger reds are retained exactly. Honest limit: how the palette reads on a real Windows desktop (real fonts, ClearType, DPI scaling) is owner-hardware verification; the proof here is the computed + render-verified contrast, the screenshot inventory, and the pixel audit.

### Added (2026-10-20 promo / test access codes)
- **Promo / test access codes (app only)** — a short code unlocks premium in the Windows app with no purchase and no contact with the payments service. The promo is built into the owner's key tool: `tools/keygen.py` carries the code in concealed (sealed) form — never in plaintext in this repo, the website, or the app — and every `build-pack` derives a real promo license from it, publishing signed metadata (`app/promo-meta.json`, bundled into the app) from which the app re-derives the license from the entered code (PBKDF2-HMAC-SHA256, per-build salt) and verifies it against the signing key before unlocking. A wrong code fails like a forged key, repeated failures back off from 5 seconds up to 5 minutes (persisted across restarts), and an unlocked promo session is labeled **"Premium — promo access"**. Certificates earned under a promo unlock are countersigned by the same `sign-cert` rules as purchased ones. Rotating the code means updating the sealed built-in in the tooling and rebuilding the pack; retiring it means removing the built-in and rebuilding — editions built without it ship the metadata as `null` and the promo card shows a plain not-active note. The website is not part of this feature and is unchanged by it.
- **Windows app v1.0.3** — adds the My Premium promo / test code card, plus a tighter My Premium layout so the payment panel keeps its guarded spacing with the new card present.

### Fixed (2026-10-20 keygen key files on Windows)
- **`tools/keygen.py setup` wrote corrupt key stores on Windows** — the key files are raw 32-byte secrets, but they were written through a text-mode descriptor (`os.open` without `O_BINARY`), so on Windows every 0x0A byte in a key was stored as 0x0D 0x0A and `load_keys` — which reads the files back in binary — refused the store as "corrupt" whenever a drawn key happened to contain a newline byte (roughly one setup in five; the public key file was corrupted the same way). This is the failure that killed the first two app-v1.0.3 Windows builds while every Linux run stayed green. Key files are now written in binary mode end-to-end, and `app/tests/test_keygen_keyfiles.py` regression-tests the setup → load round-trip under a model of the Windows CRT translation with forced newline-laden key bytes.

### Release train (2026-10-20 app-v1.0.3 cuts)
- **app-v1.0.3 shipped on its third cut.** The first cut's Windows build failed in the app test step on the genuine `tools/keygen.py` key-file defect recorded above (since fixed in product code). The second cut failed the same step on a defect in the regression test itself: its Windows CRT model wrapped `os.write` unconditionally, so on a real Windows runner — where a descriptor opened without `O_BINARY` is already a genuine text-mode descriptor — the model's translation stacked on top of the CRT's own and every 0x0A landed as 0x0D 0x0D 0x0A, failing the model's own control test while Linux stayed green. The model now supplies the CRT only where the host has none and steps aside on Windows, where the control exercises genuine text mode instead; no assertion was weakened, and the control still proves an unflagged write is translated while an `O_BINARY` write is not. Product code is identical between the second cut and the shipped cut — the entire diff is `app/tests/test_keygen_keyfiles.py` (the corrected model) and this changelog note.

### Changed (2026-10-19 course expansion)
- **Course expanded to 46 modules across 7 tracks**, all built to one enterprise curriculum template: learning objectives, prerequisites/level, lessons with worked case breakdowns, a hands-on exercise, a knowledge check with answer feedback, key takeaways, a glossary, further reading, and a **certification alignment** note. Track 1 (Scam Defense Core) gained AI Voice Clones (20), Pig Butchering (21), Rental & Housing Scams (22), Refund & Overpayment Scams (23), Business Email Compromise (24), and Account Takeover Recovery (25). New cert-mapped tracks: IT Foundations (26–29, A+/Network+ domains), Security Core (30–33, Security+/CySA+), Offensive Security (34–36, PenTest+/CEH/eJPT + PNPT/OSCP readiness), Systems & Cloud (37–40, Linux+/CCNA/Azure/AWS), Physical Installs & Safety (41–43, BICSI/ESA/OSHA pathways), Professional Pathways (44–46, the Sentinel credential standard, Missouri guard/PI licensing pathways, ASIS, PMP/ITIL orientation). Alignment means the course teaches the knowledge domains those certifications test — it confers no certification or license, and hands-on/state-issued credentials are taught as pathways. The three long-form modules and three micro-lessons under `course/` were expanded to the same standard.
- **The game is removed from the live product** ("YOU ARE THE SCAMMER" scenarios, ranks, and game framing) — the product is the course now. Free tier = modules 01–03; premium = all 46 modules + the final exam. The premium pack is course-only (43 premium modules). Game code remains recoverable in git history.
- **The course is becoming an installable Windows app** (in development): the web assets stay self-contained and offline-safe for the app shell, and this Pages site serves as the landing/download front door, the public certificate verify page, and the free web preview.
- **Buy page — automated fulfillment, wired to the payments service contract** (`payments/README.md`): enter email → create an order → the service assigns a unique exact BTC amount → pay from a wallet you control → payment detected on-chain automatically → license key generated and emailed automatically at 1 confirmation. No accounts — the key itself is the account, and the order ID is the claim credential (the status checker shows the key once paid). Wrong-amount/exchange payments fall back to manual resolution by transaction ID, as before. One configurable constant (`PAYMENTS_API_BASE` in `game/buy.html`) wires the service; until it is set, the page runs an interim mode (live CoinGecko amount + the manual paths).
- **Copy protection** on course content and exam questions: text selection disabled, copy/cut intercepted with a polite notice, context menu and drag suppressed on protected content. A deterrent layer (not absolute — view-source and screenshots can't be prevented on the web); certificates, form fields, and paste-into-license-key are unaffected.
- **Exam integrity monitoring:** local behavioral signals (tab switches, window blurs, copy/cut/paste attempts, per-question timing, total duration) summarized into a clean/flagged verdict embedded in the certificate payload. `tools/keygen.py sign-cert` surfaces the verdict prominently and warns when flagged — the seller decides; genuine certificates validate exactly as before (score 72–90, percentage consistency, license binding unchanged).
- **Certificate email delivery:** on a pass, the exam page submits the certificate code + license key (required to verify the code's proof) + integrity block to the service (`PAYMENTS_API_BASE` in `exam.html` → `POST /api/certificates`). Clean verdicts are countersigned and emailed automatically, and the returned countersigned code lights the verified seal on the page; flagged verdicts return "held for review" and the student sees a calm review message (never an accusation). The on-page certificate remains the instant copy; the manual email route remains available.
- README, TERMS, and PRIVACY rewritten course-only with true counts; PRIVACY documents the integrity signals and the automated purchase/certificate flows.

### Fixed (2026-10-19 hardening sweep)
- `tools/keygen.py mint` now validates `--days` (1–3650) — a 0/negative value previously minted a license that was already expired on arrival
- Game: a remembered license is no longer wiped at boot when only the premium pack fails to load (e.g. pack not deployed yet) — the key stays saved if the license itself still verifies; only genuinely bad/expired keys are forgotten
- Game: all scenario / premium-pack / manifest text is HTML-escaped at render time (defense-in-depth; the content carries no intended HTML)

- Verifier: unsigned certificate codes now show only the certificate ID — holder/score fields in an unsigned payload are unauthenticated and are no longer rendered
- Removed dead `S.pending` state from the game
